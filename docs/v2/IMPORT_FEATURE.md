# External Knowledge Import Feature

## Overview

The **Import** feature allows you to import external documentation (PRDs, technical specifications, implementation handoffs, integration docs) into SPEKY and automatically decompose them into structured, implementable specs.

**Key capabilities:**
- 📚 Import from folders or individual files
- 🔍 AI-powered document analysis and decomposition
- ✅ Interactive review before committing to import
- 🔄 Reconciliation between code and imported docs
- 📋 Traceability from specs back to source documents

---

## Quick Start

### Step-by-Step Workflow

```bash
# Step 1: Create the import folder
speky import --phase mvp
# Creates: .speky/imports/mvp/source/

# Step 2: Place your documents in the folder
# Copy your PRD, technical specs, etc. to:
# .speky/imports/mvp/source/

# Step 3: Run import again to process documents
speky import --phase mvp
# This will scan, analyze, and propose specs

# Step 4 (Optional): Import without interactive review
speky import --phase mvp --no-review
```

### Folder Location

Documents are placed in a **predefined location** within your project:

```
.speky/
└── imports/
    └── <phase>/
        └── source/           # ← Place your documents here
            ├── product_prd.md
            ├── technical_spec.md
            └── api_design.md
```

**Supported formats:** `.md`, `.txt`, `.pdf`, `.docx`

### Check Import Status

```bash
# Show all imports and their derived specs
speky import-status
```

### Reconcile Code with Imports

```bash
# After implementation, reconcile code with imported docs
speky reconcile mvp

# Preview changes without applying
speky reconcile mvp --dry-run

# Reconcile specific spec only
speky reconcile mvp --spec 001
```

## Folder Structure

Imports are organized in `.speky/imports/`:

```
.speky/
├── imports/
│   ├── mvp/                          # One folder per import phase
│   │   ├── source/                   # ← Place your documents HERE
│   │   │   ├── product_prd.md
│   │   │   ├── technical_spec.md
│   │   │   └── api_integration.md
│   │   ├── manifest.json             # Import metadata (auto-generated)
│   │   ├── analysis.md               # AI analysis (auto-generated)
│   │   └── roadmap.md                # Implementation roadmap (auto-generated)
│   │
│   └── v2-features/
│       ├── source/                   # Documents for v2 features
│       └── ...
│
├── specs/                            # Specs created from imports
│   ├── 001-video-upload/
│   │   ├── spec.md
│   │   ├── status.json               # Includes import_source
│   │   └── plan.md
│   └── ...
```

**Key Point:** You only interact with the `source/` folder. Everything else is auto-generated by SPEKY.

## Workflow: Pre-Import Interactive Review

### Step 1: Create Folder & Add Documents

```bash
$ speky import --phase mvp

# If folder doesn't exist, SPEKY creates it:
📚 Import External Knowledge
   Created import folder: .speky/imports/mvp/source/

📋 Next steps:
   1. Place your documents in: .speky/imports/mvp/source/
      (Supported: .md, .txt, .pdf, .docx)
   2. Run: speky import --phase mvp
```

### Step 2: Run Import

After placing your documents in `.speky/imports/mvp/source/`:

```bash
$ speky import --phase mvp

📂 Scanning Documents
   Location: .speky/imports/mvp/source/
   Found 3 document(s):
   • product_prd.md (12KB)
   • technical_spec.md (8KB)
   • api_integration.md (5KB)

📊 Analyzing Content...
   ✅ Analysis complete
```

### Step 3: Interactive Review

For each proposed spec, you can:

```
──────────────────────────────────────────────────────────────────
Proposed Spec 1/4: Video Upload Service
──────────────────────────────────────────────────────────────────

📝 Scope: Handle video uploads up to 500MB with progress tracking
⏱️  Estimate: 12 hours
📄 Source: product_prd.md (Section 3.1)

Action: [a]ccept [m]odify [s]plit [r]emove [q]uestion [n]ext [p]revious
```

**Options:**

| Action | Description |
|--------|-------------|
| **[a]ccept** | Accept the proposed spec as-is |
| **[m]odify** | Change name, scope, estimate, or add notes |
| **[s]plit** | Split into multiple smaller specs |
| **[r]emove** | Remove this spec from import |
| **[q]uestion** | Ask AI clarifying questions |
| **[n]ext** | Move to next spec |
| **[p]revious** | Go back to previous spec |

### Step 3: Modify Specs

When you choose `[m]odify`, you can:

```
Modifying: Video Upload Service
   1. Change name
   2. Reduce scope
   3. Expand scope
   4. Change estimate
   5. Add notes

What to modify: 2

Reduced scope: [current scope]
> File upload with chunked transfer only (remove progress UI for MVP)

Updated scope:
   ✓ File upload with chunked transfer
   ✗ Progress tracking UI (REMOVED → Out of Scope)
   ✓ Format validation (mp4, mov, avi)
   ✗ Cloud storage integration (REMOVED → Out of Scope)

Want to create a separate spec for removed items? [y/N]: y
✅ Will create: "002-upload-enhancements" for removed items
```

### Step 4: Ask Questions

When you choose `[q]uestion`, AI provides analysis:

```
Your question: The PRD mentions both Whisper and Google Speech API. 
               Which should we use for MVP?

🤖 AI Analysis:
   The PRD mentions both as options:
   - Whisper: Better accuracy, self-hosted, no API costs
   - Google Speech: Faster setup, pay-per-use, cloud dependency
   
   For MVP, I recommend Whisper because:
   1. PRD Section 5.2 mentions "minimize external dependencies"
   2. Technical spec prefers self-hosted for data privacy
   
   However, the PRD is ambiguous on this.

Would you like to:
   1. Proceed with Whisper (update spec)
   2. Proceed with Google Speech (update spec)
   3. Keep both as options (defer decision)
   4. Update source document with your decision
```

### Step 5: Merge/Split Specs

```
Proposed Spec 3/4: Recipe Parser
Proposed Spec 4/4: Ingredient Extractor

💡 AI Note: These specs are closely related and could be merged.

Action: [a]ccept both [m]erge into one [k]eep separate [q]uestion

Choice: m

Merging:
  • Recipe Parser (4.1)
  • Ingredient Extractor (4.2)

Name for merged spec: Recipe & Ingredient Processing

Combined scope:
  • Parse transcription into recipe steps
  • Extract ingredients with quantities
  • Handle cooking terminology
  • Output structured recipe format

Estimated: 16 hours (was 10 + 8 = 18)

✅ Merged into single spec: "003-recipe-ingredient-processing"
```

### Step 6: Final Summary

```
══════════════════════════════════════════════════════════════════
📋 IMPORT SUMMARY
══════════════════════════════════════════════════════════════════

Specs to create (3):
  ✅ 001-video-upload (modified - reduced scope)
  ✅ 002-upload-enhancements (new - from removed items)
  ✅ 003-recipe-ingredient-processing (merged)

Source document updates (1):
  📝 technical_spec.md - Transcription provider decision

Notes added (1):
  📝 001-video-upload: "MVP should use local storage first"

❓ Proceed with import? [y/n/r/e]: y

✅ Import complete!
   • 3 specs created in .speky/specs/
   • Import manifest saved to .speky/imports/mvp/
```

## Workflow: Post-Implementation Reconciliation

After implementing specs, reconcile code with imported docs to ensure alignment:

```bash
$ speky reconcile mvp

🔄 RECONCILIATION: Phase mvp
──────────────────────────────────────────────────────────────────

Analyzing:
  • Import source: .speky/imports/mvp/
  • Derived specs: 001, 002, 003
  • Current codebase...

⚠️  Mismatch 1/3: Video Upload Implementation
──────────────────────────────────────────────────────────────────

📄 Import Source (product_prd.md):
   "Videos up to 500MB with chunked upload"

📋 Spec (001-video-upload):
   "File upload with chunked transfer, max 500MB"

💻 Current Code (services/upload_service.py):
   MAX_FILE_SIZE = 100 * 1024 * 1024  # 100MB
   # Uses simple upload, not chunked

🔍 Discrepancies:
   1. File size: PRD says 500MB, code has 100MB
   2. Upload method: PRD/spec say chunked, code uses simple upload

How would you like to resolve this?
   1. Update code to match PRD/spec (implement chunked, 500MB)
   2. Update PRD & spec to match code (simple upload, 100MB is enough)
   3. Partial: Update size limit only (keep simple upload for MVP)
   4. Ask clarifying question
   5. Skip (defer resolution)

Choice: 4
```

### Clarifying Questions

```
Your question: Why was 100MB chosen? Is 500MB actually needed?

🤖 AI Analysis:
   Looking at the codebase and PRD context:
   
   PRD Section 3.1 mentions: "typical cooking videos are 5-15 minutes"
   At 1080p, that's roughly 50-150MB.
   
   The 500MB limit in PRD seems like a safety margin.
   100MB in code might be a deployment constraint.
   
   Recommendation: 200MB is likely sufficient for MVP.
   Chunked upload matters more for reliability than size.

Based on this, would you like to:
   1. Set limit to 200MB, add chunked upload (balanced approach)
   2. Keep 100MB, add chunked upload (conservative)
   3. Set to 500MB as PRD says (follow original spec)
   4. Specify your own resolution

Choice: 1

This will:
  📝 Update product_prd.md: Change 500MB → 200MB with rationale
  📋 Update spec 001: Reflect 200MB limit
  💻 Create task: Implement chunked upload (added to plan)

Apply these changes? [Y/n]: y

✅ Updated: product_prd.md (Section 3.1)
✅ Updated: .speky/specs/001-video-upload/spec.md
✅ Added task to: .speky/specs/001-video-upload/plan.md
```

### Dry Run Mode

Preview changes without applying:

```bash
$ speky reconcile mvp --dry-run

🔄 RECONCILIATION: Phase mvp (Dry Run)
──────────────────────────────────────────────────────────────────

Mismatches (Dry Run):

1. Video Upload Implementation
   Description: File size limit differs (500MB vs 100MB)

2. Authentication Method
   Description: OAuth not implemented, only email/password

3. API Versioning
   Description: Code uses v1, spec mentions v2 compatibility

(No changes applied - use without --dry-run to apply)
```

## Document Type Detection

SPEKY automatically detects document types:

| Type | Keywords | Purpose |
|------|----------|---------|
| **product** | user story, acceptance criteria, epic, feature | Product requirements and user-facing features |
| **technical** | architecture, api, database, schema, technical | Technical design and implementation approach |
| **integration** | integration, external, third-party, webhook | External system integration |
| **security** | security, compliance, pci, gdpr, requirement | Security and compliance requirements |
| **implementation** | step, task, instruction, implementation, handoff | Step-by-step implementation guides |
| **general** | (other) | General documentation |

## Spec Traceability

Each spec created from import includes source information in `status.json`:

```json
{
  "id": "001",
  "name": "Video Upload",
  "status": "draft",
  "created": "2024-01-15T10:30:00Z",
  "import_source": {
    "phase": "phase-mvp",
    "document": "product_prd.md (Section 3.1)"
  }
}
```

This allows you to:
- Track which requirement came from which document
- Link back to original source for context
- Maintain traceability through implementation

## Best Practices

### 1. **Use Interactive Review**
Always use interactive review (default) to:
- Catch AI misunderstandings early
- Adjust scope before creating specs
- Ask clarifying questions
- Merge/split specs as needed

### 2. **Organize by Phase**
Use meaningful phase names:
```bash
# Each phase gets its own folder
speky import --phase mvp
speky import --phase v2-features
speky import --phase payments

# Documents go in:
# .speky/imports/mvp/source/
# .speky/imports/v2-features/source/
# .speky/imports/payments/source/
```

### 3. **Keep Source Documents**
Original documents are preserved in `.speky/imports/<phase>/source/`:
- Reference them during planning
- Update them with decisions made during review
- Maintain traceability

### 4. **Reconcile After Implementation**
Use reconciliation to:
- Ensure code matches imported requirements
- Resolve ambiguities with clarifying questions
- Update docs/specs when code deviates
- Create tasks for unimplemented features

### 5. **Leverage Traceability**
Use import source information to:
- Link specs back to requirements
- Understand rationale for decisions
- Maintain requirements traceability
- Support future audits/compliance

## Troubleshooting

### No documents found
- Ensure documents are in `.speky/imports/<phase>/source/`
- Check file extensions: `.md`, `.txt`, `.pdf`, `.docx`
- Ensure files are readable

### AI analysis seems wrong
- Use interactive review to ask clarifying questions
- Modify proposed specs before importing
- Check document clarity and completeness

### Reconciliation detects too many mismatches
- Use `--dry-run` to preview before applying
- Ask clarifying questions to understand context
- Update source documents if they're outdated

### Specs created but not as expected
- Review the analysis: `.speky/imports/<phase>/analysis.md`
- Check the roadmap: `.speky/imports/<phase>/roadmap.md`
- Modify specs after import using `speky validate-spec`
