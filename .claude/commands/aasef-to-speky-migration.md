# AASEF → SPEKY Migration

Migrate a project from the legacy `aasef` framework to `speky`.

**Usage:** `/aasef-to-speky-migration` (run from inside the target project), or pass the project path as `$ARGUMENTS`.

---

## Context

AASEF was the original name of the Speky framework. Projects built with it have:
- A `.aasef/` directory containing specs, stories, epics, context, config, and imports
- Auto-generated IDE rule files (`.windsurfrules`, `.cursorrules`, `CLAUDE.md`, `.agent/rules/*.md`) that reference `.aasef/` paths and `aasef` commands
- Content inside `.aasef/specs/`, `.aasef/stories/`, `.aasef/workflow_guides/`, `.aasef/testing/` that references `aasef` commands
- Test files and docs outside `.aasef/` with hardcoded `.aasef/` path strings

`speky.py` hardcodes `SPEKY_DIR = ".speky"`, so the directory rename is mandatory for any `speky` command to work.

---

## Pre-Migration Audit

Before changing anything, run this audit to understand the scope:

```bash
PROJECT="$ARGUMENTS"
if [ -z "$PROJECT" ]; then PROJECT=$(pwd); fi
echo "Target project: $PROJECT"

# Confirm .aasef exists
ls "$PROJECT/.aasef/" 2>/dev/null || echo "ERROR: .aasef not found"

# Count data to be migrated
echo "Specs:   $(ls "$PROJECT/.aasef/specs/" 2>/dev/null | wc -l | tr -d ' ')"
echo "Stories: $(ls "$PROJECT/.aasef/stories/" 2>/dev/null | wc -l | tr -d ' ')"
echo "Epics:   $(ls "$PROJECT/.aasef/epics/" 2>/dev/null | wc -l | tr -d ' ')"

# Find all files with aasef references outside .aasef/
grep -r "aasef" "$PROJECT/" \
  --exclude-dir=.aasef \
  --exclude-dir=node_modules \
  --exclude-dir=.git \
  -l 2>/dev/null
```

Identify from the output:
1. Auto-generated IDE files: `.windsurfrules`, `.cursorrules`, `CLAUDE.md`, `.agent/rules/*.md`
2. Source code with hardcoded `.aasef/` paths (e.g., test files checking file existence)
3. Non-auto-generated docs (README, HANDOFF notes, etc.)
4. Archive files (usually in `project_ops/archives/` or `**/OLD_*`) — **leave these unchanged**

## Migration Steps

### Step 1 — Rename the Data Directory

```bash
PROJECT="$ARGUMENTS"
if [ -z "$PROJECT" ]; then PROJECT=$(pwd); fi
mv "$PROJECT/.aasef" "$PROJECT/.speky"
echo "Renamed .aasef → .speky"
ls "$PROJECT/.speky/"
```

Verify all subdirectories moved: `specs/`, `stories/`, `context/`, `config.yaml`. Epics, imports, testing, and workflow_guides may also be present.

### Step 2 — Update the Config Header Comment

Read `$PROJECT/.speky/config.yaml`. If the first line is `# AASEF Configuration`, change it to `# SPEKY Configuration`.

### Step 3 — Bulk Replace Inside the .speky/ Directory

All spec files, story files, workflow guides, testing tasks, and the testing `ide_context.md` contain references to `aasef` commands and `.aasef/` paths. Replace them all in one pass:

```bash
PROJECT="$ARGUMENTS"
if [ -z "$PROJECT" ]; then PROJECT=$(pwd); fi

find "$PROJECT/.speky/" -type f \
  \( -name "*.md" -o -name "*.yaml" -o -name "*.yml" -o -name "*.json" -o -name "*.archive" \) \
  | while read f; do
    sed -i '' \
      -e 's/\.aasef\//.speky\//g' \
      -e 's/AASEF/SPEKY/g' \
      -e 's/aasef test /speky test /g' \
      -e 's/aasef implement /speky implement /g' \
      -e 's/aasef complete /speky complete /g' \
      -e 's/aasef spec /speky spec /g' \
      -e 's/aasef story /speky story /g' \
      -e 's/aasef adopt /speky adopt /g' \
      -e 's/aasef import /speky import /g' \
      -e 's/aasef status/speky status/g' \
      -e 's/aasef sync/speky sync/g' \
      -e 's/aasef sequence/speky sequence/g' \
      -e 's/aasef plan /speky plan /g' \
      -e 's/aasef backlog/speky backlog/g' \
      -e 's/aasef design/speky design/g' \
      -e 's/aasef phases/speky phases/g' \
      -e 's/aasef validate/speky validate/g' \
      -e 's/aasef_testing/speky_testing/g' \
      "$f"
  done

# Verify clean
REMAINING=$(grep -r "aasef\|AASEF" "$PROJECT/.speky/" --include="*.md" --include="*.yaml" --include="*.json" -l 2>/dev/null)
[ -z "$REMAINING" ] && echo ".speky/ directory: CLEAN" || echo "Still found: $REMAINING"
```

If the bulk pass shows remaining files, read them and fix edge cases manually (e.g., ASCII art containing `aasef`, inline anchor links like `#aasef-test-commands`).

**Important:** Also fix `$PROJECT/.speky/context/codebase.md` specifically — it may have a stale directory listing that says `.aasef/`:
```bash
grep -n "aasef\|AASEF" "$PROJECT/.speky/context/codebase.md"
# If found, edit it: .aasef/ → .speky/, AASEF → SPEKY
```

**Also check `context.json`** — it stores a `codebase.structure` JSON string that may contain `.aasef/`:
```bash
grep "\.aasef" "$PROJECT/.speky/context/context.json" && echo "needs fix" || echo "clean"
# The sed pass above covers this, but verify
```

### Step 4 — Delete Auto-Generated IDE Files

These files are fully regenerated by `speky`. Delete them — do NOT manually edit:

```bash
PROJECT="$ARGUMENTS"
if [ -z "$PROJECT" ]; then PROJECT=$(pwd); fi

# Check headers first to confirm they are auto-generated
head -2 "$PROJECT/.windsurfrules" 2>/dev/null
head -2 "$PROJECT/CLAUDE.md" 2>/dev/null

# Only delete if header says "Auto-generated by AASEF"
rm -f "$PROJECT/.windsurfrules"
rm -f "$PROJECT/.cursorrules"
rm -f "$PROJECT/CLAUDE.md"
rm -f "$PROJECT/.agent/rules/01-aasef-core.md"
rm -f "$PROJECT/.agent/rules/01-aasef-essentials.md"
rm -f "$PROJECT/.agent/rules/02-aasef-structure.md"
rm -f "$PROJECT/.agent/rules/03-aasef-context.md"
# Remove any other .agent/rules/*aasef*.md files
find "$PROJECT/.agent/rules/" -name "*aasef*" -delete 2>/dev/null
echo "Deleted auto-generated aasef IDE rule files"
ls "$PROJECT/.agent/rules/" 2>/dev/null
```

**IMPORTANT:** If an IDE file has manual custom content (not auto-generated), update it in place instead — replace `.aasef/` → `.speky/` and `aasef ` → `speky ` throughout.

### Step 5 — Fix Source Code with Hardcoded Paths

Find test files and code that reference `.aasef/context/` paths:

```bash
PROJECT="$ARGUMENTS"
if [ -z "$PROJECT" ]; then PROJECT=$(pwd); fi
grep -rn "\.aasef" "$PROJECT/" \
  --include="*.ts" --include="*.tsx" \
  --include="*.js" --include="*.jsx" \
  --include="*.py" --include="*.go" \
  --exclude-dir=node_modules --exclude-dir=.git
```

For each match, use the Edit tool to replace `.aasef/` → `.speky/`. Also update any string literals like `"AASEF"` in test descriptions.

Common pattern:
```typescript
// Before
const path = join(PROJECT_ROOT, '.aasef/context/codebase.md');
// After
const path = join(PROJECT_ROOT, '.speky/context/codebase.md');
```

### Step 6 — Update Non-Archive Docs

Find non-auto-generated markdown docs with aasef references:

```bash
PROJECT="$ARGUMENTS"
if [ -z "$PROJECT" ]; then PROJECT=$(pwd); fi
grep -rl "aasef\|AASEF" "$PROJECT/" \
  --include="*.md" \
  --exclude-dir=.aasef --exclude-dir=.speky \
  --exclude-dir=node_modules --exclude-dir=.git 2>/dev/null | \
  grep -v "archives\|OLD_\|old_"
```

For each file, run:
```bash
sed -i '' \
  -e 's/\.aasef\//.speky\//g' \
  -e 's/AASEF/SPEKY/g' \
  -e 's/aasef /speky /g' \
  "$FILE"
```

Then spot-check for edge cases like anchor links (`#aasef-test-commands` → `#speky-test-commands`).

Skip archive files: `project_ops/archives/`, `**/OLD_*`, `**/old_*`.

### Step 7 — Read the Enabled IDEs from Config

```bash
PROJECT="$ARGUMENTS"
if [ -z "$PROJECT" ]; then PROJECT=$(pwd); fi
cat "$PROJECT/.speky/config.yaml" | grep -E "ide:|enabled_ides"
python3 -c "import json; d=json.load(open('$PROJECT/.speky/context/context.json')); print('enabled_ides:', d.get('enabled_ides', d.get('ide', 'windsurf')))"
```

Note the enabled IDEs (e.g., `windsurf`, `cursor`, `claude-code`, `antigravity`).

### Step 8 — Regenerate IDE Files

Ensure `speky` is on PATH:
```bash
which speky || pip install speky --break-system-packages
```

Then regenerate all IDE rule files from inside the project directory:
```bash
cd "$PROJECT"
speky config --ides set <comma-separated-ides-from-step-7>
# Example: speky config --ides set windsurf,antigravity,claude-code
```

This creates `CLAUDE.md`, `.windsurfrules`, `.cursorrules`, and `.agent/rules/01-speky-core.md` etc. with all references pointing to `.speky/` and using `speky` commands.

### Step 9 — Verification

```bash
PROJECT="$ARGUMENTS"
if [ -z "$PROJECT" ]; then PROJECT=$(pwd); fi
cd "$PROJECT"

echo "=== Data Integrity ==="
echo "Specs:   $(ls .speky/specs/ 2>/dev/null | wc -l | tr -d ' ')"
echo "Stories: $(ls .speky/stories/ 2>/dev/null | wc -l | tr -d ' ')"
echo "Context: $(ls .speky/context/)"
echo ""

echo "=== speky status ==="
speky status

echo ""
echo "=== .aasef gone ==="
ls -la .aasef 2>/dev/null && echo "WARNING: .aasef still exists" || echo "Confirmed gone"

echo ""
echo "=== Zero aasef refs (outside archives) ==="
REMAINING=$(grep -r "aasef\|AASEF" . \
  --exclude-dir=node_modules \
  --exclude-dir=.git \
  -l 2>/dev/null | grep -v "archives\|OLD_\|old_")
[ -z "$REMAINING" ] && echo "CLEAN" || echo "STILL FOUND: $REMAINING"

echo ""
echo "=== IDE files regenerated ==="
head -1 CLAUDE.md 2>/dev/null
head -1 .windsurfrules 2>/dev/null
ls .agent/rules/ 2>/dev/null
```

Expected results:
- `speky status` shows all specs and stories correctly
- Zero aasef references outside archive directories
- No `.aasef` directory
- IDE files say "Auto-generated by SPEKY"
- `.agent/rules/` has `01-speky-core.md` (not `01-aasef-core.md`)

### Step 10 — Run Project Tests

```bash
cd "$PROJECT"
# Detect test command
if [ -f "pnpm-workspace.yaml" ]; then
  pnpm test 2>&1 | tail -20
elif [ -f "package.json" ]; then
  npm test 2>&1 | tail -20
fi
```

All tests that previously checked `.aasef/context/*.md` paths should pass against `.speky/context/`. Any remaining failures are pre-existing issues unrelated to the migration.

### Step 11 — Commit

```bash
cd "$PROJECT"
git add .speky/ .agent/rules/ CLAUDE.md .windsurfrules .cursorrules 2>/dev/null
git add -u  # Stage deletions of old .aasef/ files
git status

git commit -m "chore: migrate from aasef to speky

- Renamed .aasef/ → .speky/ (all specs, stories, context preserved)
- Deleted auto-generated aasef IDE rule files (regenerated by speky)
- Updated hardcoded .aasef/ paths in test and source files
- Updated aasef command references throughout specs, stories, and docs"
```

## Common Issues Found During Dogfooding

**`.speky/testing/ide_context.md` injects aasef into IDE files:**
This file is source data that speky appends to IDE rules. The bulk sed in Step 3 handles it via the `.speky/` directory pass — but double-check it's clean before regenerating IDE files in Step 8.

**`.speky/context/context.json` has embedded codebase snapshot:**
The `codebase.structure` key stores a JSON-encoded copy of codebase.md content. The bulk sed handles this, but verify:
```bash
grep "\.aasef" .speky/context/context.json
```

**Anchor links in markdown survive AASEF→SPEKY text substitution:**
Markdown anchors like `[SPEKY Test Commands](#aasef-test-commands)` — the display text gets updated but the anchor URL does not. Grep specifically for lowercase `#aasef-` anchors and fix them manually.

**Auto-generated `.cursorrules` check:**
If the project uses Cursor IDE, `.cursorrules` exists and is auto-generated. The `rm -f` in Step 4 silently skips if it doesn't exist — safe either way.

**`speky config --ides set` may reset cwd:**
Speky resets the shell working directory after running. This is cosmetic — your actual cwd is unchanged.

**Pre-existing test failures vs migration failures:**
Some spec tests check content accuracy in context files (e.g., "codebase.md must contain `@spayce/core`"). These may have been failing before migration. Only failures about `.aasef/` path existence indicate a migration issue.

---

## What Does NOT Change

- All spec content (`spec.md`, `plan.md`) — content preserved, only `aasef` command names updated
- All story content (`story.md`) — same
- `status.json` files — no aasef references, unchanged
- Config values (model, tokens, timeout) — unchanged
- Context files (`product.md`, `tech_decisions.md`, `codebase.md`, etc.) — only directory path references updated
- Git history — `git log -- .speky` shows all prior commits from when it was `.aasef`
- Actual project source code — unchanged
- Archive files in `project_ops/archives/` — left as historical record
